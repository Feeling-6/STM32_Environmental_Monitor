# 基于 STM32 的工业级环境监测与智能报警系统

在 STM32F103C8T6 上从零实现的嵌入式环境监测系统。基于 **ST 标准外设库**裸机开发（非 HAL / 非 Arduino / 无 RTOS），采用分层驱动架构，目前已完成多传感器采集、DMA 搬运、显示、按键状态机等模块，并已全部上板验证。

> **说明**：本 README 严格区分「已实现」与「计划中」两块。**「已实现」的每一项都是实际上板跑通过的**，不是设计稿。

---

## 一、功能特性

### ✅ 已实现（上板验证通过）

**显示**
- 0.96" OLED（SSD1315 驱动芯片，128×64），硬件 I2C，**400kHz**
- 1KB 帧缓冲架构，绘图与刷屏分离，支持字符 / 数字 / 浮点数 / 画点 / 画线 / 矩形 / 进度条
- 采用**页寻址模式**，从根上规避 SSD1315 在水平寻址模式下与 `0xB0` 混用时的跨页问题

**传感器**
- SHT30 温湿度（I2C，**带 CRC-8 校验**，单次测量高重复度）
- MQ-2 烟雾 + 光敏电阻（**ADC1 双通道连续扫描 + DMA1 循环搬运**）

**人机交互**
- **6 按键驱动**：定时器中断（10ms）扫描 + 消抖预滤波 + 5 状态机
  - 支持**单击 / 双击 / 长按 / 长按重复**四种事件
  - 事件通过**无锁 SPSC 环形队列**交给主循环
- LED 状态指示（PB12）

**底层**
- I2C2 总线层：**幂等初始化 + 超时保护 + 总线死锁恢复**，被 OLED 和 SHT30 共用
- SysTick 轮询延时模块

### 🚧 计划中（尚未实现，勿在简历中声称已完成）

- 蜂鸣器 PWM 音调报警（无源蜂鸣器，TIM1_CH4）
- SD 卡数据记录（SPI1 + FATFS，带时间戳）
- IWDG 独立看门狗
- 串口日志（USART1 + `printf` 重定向）
- 低功耗模式（停机 / 待机）
- 多级菜单

| 光照 | 光敏电阻模块 | ADC1_IN1 | 3.3V 供电 |
| 按键 | 轻触开关 ×6 | GPIO 上拉输入 | 另一端接 GND，按下为低 |
| 指示 | LED + 1kΩ 限流电阻 | GPIO | **高电平点亮** |

### 引脚分配

| 模块 | 引脚 | 外设 |
|---|---|---|
| OLED / SHT30 | PB10 (SCL) / PB11 (SDA) | I2C2 |
| MQ-2 / 光敏 | PA0 / PA1 | ADC1_IN0 / IN1 |
| 6 按键 | PB13 / PB15 / PA12 / PB3 / PB5 / PB7 | GPIO |
| LED | PB12 | GPIO |
| SWD 调试 | PA13 / PA14 | — |

**注意 PB3 的坑**：PB3 默认是 **JTDO**（JTAG 引脚），当普通 GPIO 用必须先执行
`GPIO_PinRemapConfig(GPIO_Remap_SWJ_JTAGDisable, ENABLE)` 释放。
这一句同时释放 PA15/PB3/PB4，**且完整保留 SWD**，不影响 ST-Link 下载调试。
（**绝不能**用 `GPIO_Remap_SWJ_Disable` —— 那个会把 SWD 也关掉。）

## 三、软件架构

```
┌─────────────────────────────────────────────────┐
│                  src/main.c                     │   应用层
│         初始化顺序 + 主循环 + 界面逻辑            │
├─────────────────────────────────────────────────┤
│  OLED  │ SHT30 │  AD   │  Key  │  LED           │   设备层
│  显示  │ 温湿度 │ 模拟量 │  按键  │  指示          │
├─────────────────────────────────────────────────┤
│              I2C2  总线层                        │   总线层
│   幂等初始化 · 超时保护 · 死锁恢复 · 读写         │
├─────────────────────────────────────────────────┤
│         ST 标准外设库 v3.6.0 (lib/SPL)           │   芯片层
└─────────────────────────────────────────────────┘
```

**分层原则**：`I2C2` 是唯一的 I2C 时序实现，OLED 和 SHT30 都建在它上面。
新增 I2C 器件时直接复用总线层，不重复写时序。

### 三个值得展开的设计点

#### 1. 无锁 SPSC 环形队列（中断 ↔ 主循环通信）

按键中断是生产者，主循环是消费者。用环形队列传递事件，**避免"双击把单击覆盖掉"**。

```c
static volatile KeyEvent s_Queue[16];
static volatile uint8_t  s_Head;    // 只由中断写
static volatile uint8_t  s_Tail;    // 只由主循环写
```

- **不关中断**：单生产者单消费者下，双方各自只读对方的指针，没有读-改-写竞争
- **不需要内存屏障**：Cortex-M3 无 D-Cache，`uint8_t` 读写是单条指令、天然原子
- **`s_Queue` 必须同时是 `volatile`**：它保证"先写载荷、再发布头指针"的发布顺序不被编译器重排
- **满时丢弃最新事件**：丢最旧需要生产者推进 `s_Tail`（消费者的变量），会引入需要临界区的竞争

#### 2. 按键状态机（5 状态，含超时逃逸）

分两层：**消抖预滤波** + **业务状态机**。消抖层要求连续 N 次采样一致才认可，
于是状态机只需处理"已消抖的布尔值"，**5 个状态全是业务语义，一个消抖状态都不用写**。

```
①IDLE ──按下──> ②PRESSED ──松开──> ③WAIT ──第二击按下──> ⑤PRESSED2
                   │                    │                      │
              长按满1s              窗口超时                松开 → ①
                   ↓                    ↓
              ④LONG ──松开→①      发CLICK→①
              （每200ms发LONG_REPEAT）
```

两个来自实际调试的设计细节：

- **状态 ⑤ 必须有超时逃逸**。最初版本它只有"松开 → IDLE"一条路径，结果
  "双击后按住不放"会让状态机**永远停住** —— 不产生事件、状态不变，那个按键在物理松开前完全失效
- **`Armed` 上电保护**：上电时必须先见到一次"松开"才启动状态机。否则**复位时手指正按着键**，
  会在一秒后莫名报一次长按

#### 3. ADC + DMA 循环搬运（CPU 零等待）

ADC1 连续扫描两个通道，DMA1_Channel1 循环模式把结果搬进数组，**CPU 读取只是一次内存访问**。

关键约束：**`DMA_BufferSize` 必须严格等于 `ADC_NbrOfChannel`**。
这个相等关系是"数组下标 ↔ 规则组 rank ↔ 通道"成立的唯一依据，
写错会导致两路数据串位——**而且不报任何错误**。

## 四、编译与烧录

需要 [PlatformIO](https://platformio.org/) 和 ST-Link 调试器。

```bash
pio run              # 编译
pio run -t upload    # 烧录（ST-Link）
pio run -t clean     # 清理
```

> **Windows 上如果 `pio` 不在 PATH 里**，用全路径：`~/.platformio/penv/Scripts/pio.exe`

编译**只有一条已知警告**（可忽略）：

```
lib\Hardware\OLED_Font.h:6:1: warning: missing braces around initializer
```

这是字库文件的扁平花括号写法，**数据完全正确**，改成嵌套花括号没有意义。
